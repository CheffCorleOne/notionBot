Создай Chrome-расширение (Manifest V3) для автоматизации проверки контрагентов в Notion.



КОНТЕКСТ

В Notion есть база данных со счетами на оплату. В одной из колонок (по умолчанию

называется "счета") лежат PDF-файлы счетов. Нужно для каждой строки:

1\. Достать PDF счёта

2\. Извлечь из текста БИН/ИИН именно ПОСТАВЩИКА (не покупателя — БИН нашей компании

&#x20;  известен заранее и должен исключаться)

3\. Отправить этот БИН в API КГД МФ РК ("Сведения по контрагентам") и получить

&#x20;  налоговый режим контрагента (поле taxMode.ru в ответе)

4\. Записать результат в новую колонку Notion (по умолчанию "Налоговый режим"),

&#x20;  рядом с колонкой PDF



ТРИГГЕР

На странице Notion (https://\*.notion.so/\*) должна появляться плавающая кнопка

"Проверить контрагентов" (фиксированная, правый нижний угол). По клику расширение

массово обрабатывает ВСЕ строки базы, где PDF есть, а колонка "Налоговый режим" ещё

пустая — то есть заполняет только новые/необработанные строки, не трогая уже

заполненные. Во время работы показывать тост с прогрессом ("Обрабатываю 3/12...").



АРХИТЕКТУРА

\- background.js — service worker (type: module), вся логика и сетевые запросы

&#x20; (host\_permissions на api.notion.com, openrouter.ai, portal.kgd.gov.kz избавляют

&#x20; от CORS-проблем в контексте service worker)

\- content.js + styles.css — только кнопка на странице Notion + приём прогресс-сообщений

&#x20; через chrome.runtime.onMessage / chrome.tabs.sendMessage

\- popup.html + popup.js — форма настроек, значения хранятся в chrome.storage.local:

&#x20; - Notion Integration Token

&#x20; - ID базы данных Notion

&#x20; - название колонки с файлом (default: "счета")

&#x20; - название колонки результата (default: "Налоговый режим")

&#x20; - БИН/ИИН нашей компании (покупателя, для исключения)

&#x20; - OpenRouter API Key

&#x20; - модель OpenRouter (default: anthropic/claude-3.5-haiku)

&#x20; - X-Portal-Token для API КГД



ИЗВЛЕЧЕНИЕ ТЕКСТА PDF

Использовать pdfjs-dist (legacy build, .mjs), локально забандленный в lib/

(pdf.min.mjs + pdf.worker.min.mjs), workerSrc через chrome.runtime.getURL.

Не использовать eval/remote code (запрещено в MV3). Файл счёта скачивается

по временной ссылке из свойства Notion (page.properties\[fileColumn].files\[0].file.url).



ИЗВЛЕЧЕНИЕ БИН ПОСТАВЩИКА ЧЕРЕЗ OPENROUTER

Не регуляркой (шаблоны счетов у разных поставщиков разные, регулярка путает

покупателя с поставщиком). Отправлять текст счёта в OpenRouter

(POST https://openrouter.ai/api/v1/chat/completions, Bearer-токен), просить модель

вернуть строгий JSON {"xin": "12 цифр или null", "confidence": "high|medium|low"},

явно указав в промпте БИН нашей компании как "не возвращать этот".



NOTION API

\- Через api.notion.com/v1, Bearer токен интеграции, header Notion-Version: 2022-06-28

\- Перед обработкой проверить/создать колонку результата (PATCH /v1/databases/{id}),

&#x20; если её ещё нет (rich\_text property)

\- Запрос строк: POST /v1/databases/{id}/query с фильтром

&#x20; (файл колонка is\_not\_empty AND результат колонка is\_empty), с пагинацией по cursor

\- Запись результата: PATCH /v1/pages/{page\_id}, rich\_text со значением taxMode

&#x20; (или текстом ошибки, если что-то не удалось — чтобы было видно, что нужно

&#x20; вмешательство вручную)



API КГД (пример из документации, приложу отдельно)

POST \[portal-host]/services/isnaportal/public/get-sur-data

Headers: X-Portal-Token

Body: {"xin": "..."}

Обрабатывать коды ответа: 200 успех, 400 синтаксис, 401 не авторизован,

404 доступ запрещён, 500 ошибка сервера — коды 401/404/500 превращать

в понятный текст ошибки, который тоже пишем в Notion, а не роняем весь процесс.



ОБРАБОТКА ОШИБОК

Ошибка в одной строке не должна прерывать обработку остальных. Если PDF не

распознан / БИН не найден / API КГД недоступен — писать в колонку результата

короткое описание проблемы вместо падения. Между запросами — пауза \~400мс,

чтобы не упереться в рейт-лимиты Notion API (3 req/sec).
