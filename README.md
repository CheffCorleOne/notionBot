# Notion — проверка контрагентов (КГД)

Chrome-расширение (Manifest V3). На странице Notion с базой счетов появляется
плавающая кнопка **«Проверить контрагентов»**. По клику расширение проходит по
строкам, где есть вложение в колонке счёта, а колонка результата ещё пуста, и
для каждой:

1. скачивает прикреплённый файл счёта по временной ссылке из Notion;
2. извлекает текст из PDF, таблицы, документа, текстового файла или фото/скана;
3. через выбранного провайдера AI (**OpenRouter** или **OpenAI API** с vision-моделью)
   определяет БИН/ИИН **поставщика** (БИН нашей компании исключается);
4. запрашивает **API КГД МФ РК** — сервис «Сведения по контрагентам» — и получает налоговый режим (`taxMode.ru`) и статус плательщика НДС (`vatInfo.ru`);
5. записывает результаты в отдельные колонки Notion (по умолчанию «Налоговый режим» и «Плательщик НДС»).

Во время проверки кнопка превращается в красную **«Остановить проверку»**.
Остановка безопасна для данных: текущая строка либо дописывается целиком, либо
не трогается вовсе (останется пустой, и следующий запуск обработает её заново) —
наполовину заполненных строк не бывает.

Ошибка в одной строке не роняет процесс — вместо режима в колонку пишется
короткий текст ошибки, чтобы было видно, где нужно вмешаться вручную.

## Установка

1. `chrome://extensions` → включить **«Режим разработчика»**.
2. **«Загрузить распакованное расширение»** → выбрать эту папку.
3. Нажать на иконку расширения → заполнить настройки → **Сохранить**.

## Настройки

| Поле | Где взять |
|------|-----------|
| **Notion Integration Token** | notion.so/my-integrations → создать интеграцию → скопировать `Internal Integration Secret`. **Важно:** открыть свою базу в Notion → `•••` → *Connections* → добавить эту интеграцию, иначе API не увидит базу. |
| **ID базы данных Notion** | Из URL базы: `notion.so/<workspace>/<32-символьный-ID>?v=...` или `app.notion.com/p/<32-символьный-ID>?v=...` — это часть до `?v=`. |
| **Колонка с файлом** | Название колонки, где лежат счета/вложения (по умолчанию `Счет`). |
| **Колонка результата** | Куда писать режим (по умолчанию `Налоговый режим`). Создаётся автоматически, если её нет. |
| **Колонка статуса НДС** | Куда писать значение `vatInfo.ru` и дату `vatDate`, если она есть (по умолчанию `Плательщик НДС`). Создаётся автоматически. |
| **Последних строк за запуск** | Сколько верхних строк таблицы брать в обработку (по умолчанию `50`). Строки сортируются как в просмотре базы — по колонке `Дата оплаты` от поздних дат к ранним, — поэтому в обработку попадают те же строки, что пользователь видит вверху таблицы. |
| **БИН/ИИН нашей компании** | 12 цифр покупателя — чтобы модель не приняла его за поставщика. |
| **Провайдер AI** | Что использовать для распознавания БИН: **OpenRouter (бесплатные модели)** или **OpenAI API (свой ключ)**. Поля ключа и модели переключаются под выбранного провайдера. |
| **OpenRouter API Key** | openrouter.ai → *Keys* → создать ключ (`sk-or-...`). Нужен, если выбран провайдер OpenRouter. |
| **Модель OpenRouter** | По умолчанию `google/gemma-4-31b-it:free` (бесплатная). Можно вписать любую другую модель OpenRouter — она будет пробоваться первой, а при сбое сработает бесплатная цепочка запасных (см. ниже). |
| **OpenAI API Key** | platform.openai.com → *API keys* → создать ключ (`sk-...`). Нужен, если выбран провайдер OpenAI. |
| **Модель OpenAI** | По умолчанию `gpt-4o-mini` — мультимодальная (vision), читает и текст, и сканы/фото. При сбое пробуется `gpt-4o`. |
| **X-Portal-Token (КГД)** | Токен от Администратора КГД МФ РК для API сервиса «Сведения по контрагентам». |
| **Хост портала КГД** | По умолчанию `https://portal.kgd.gov.kz`. |
| **Скрыть кнопку на Notion** | Чекбокс в настройках. Скрывает плавающую кнопку «Проверить контрагентов» в правом нижнем углу страницы Notion. По умолчанию выключен. |

Расширение обращается к сервису «Сведения по контрагентам»:

```
POST /services/isnaportal/public/get-sur-data
Header: X-Portal-Token
Body: {"xin":"<БИН/ИИН>"}
```

При запуске расширение сначала берёт верхние N строк базы в порядке просмотра (сортировка по `Дата оплаты`, от поздних к ранним), затем внутри этого окна обрабатывает строки, где колонка с файлами не пустая, а хотя бы одна из колонок результата пуста. Уже заполненные значения не перезаписываются: например, после обновления расширение может дозаполнить только новую колонку НДС в ранее обработанных строках.

## Поддерживаемые файлы

Расширение пробует все вложения в строке по очереди и останавливается на первом
файле, из которого удалось получить БИН/ИИН поставщика:

- PDF — текст извлекается локально через `pdf.js`; если БИН по тексту не найден (скан), расширение сначала само достаёт встроенный скан из объектов PDF (JPEG/Flate-битмап) и отправляет его картинками в полном разрешении — вся страница плюс увеличенный верх с реквизитами. Если скан достать не удалось: **OpenAI** получает сам PDF-файл целиком (лимит 100 страниц / 32 МБ), для **OpenRouter** страницы рендерятся в JPEG (без платного PDF OCR);
- изображения `jpg`, `jpeg`, `jfif`, `png`, `webp`, `gif`, `bmp`, `tif`, `tiff`,
  `avif`, `heic`, `heif` — отправляются в OpenRouter как vision-запрос;
- таблицы `xlsx`, `xlsm`, `xltx`, `xltm`, `csv`, `tsv` — текст извлекается локально;
- `docx`, `txt`, `xml`, `html` — текст извлекается локально;
- старый `xls` — best effort: расширение вытаскивает читаемые строки из бинарного файла.

Расширение определяет реальный тип файла по содержимому (magic bytes), а не только по расширению — JPEG с неправильным именем тоже обработается.

Для фото и сканов используется **image vision** (модель из настроек → запасные vision-модели). PDF без текстового слоя при провайдере **OpenAI** отправляется в модель как файл (`type: file`), при OpenRouter — рендерится в картинки; платный PDF OCR OpenRouter не используется.

## Отказоустойчивость по моделям

Если выбранная модель OpenRouter не отвечает (сеть / HTTP-ошибка / пустой или
невалидный ответ), расширение автоматически пробует следующую рабочую модель из
встроенной цепочки, заданной в `FALLBACK_MODELS` (`background.js`):

```
google/gemma-4-31b-it:free  →  google/gemma-4-26b-a4b-it:free
                            →  nvidia/nemotron-3-nano-omni-30b-a3b-reasoning:free
```

Все модели цепочки бесплатные и поддерживают vision (сканы, фото), поэтому один
список используется и для текста, и для изображений. Ваша модель из настроек
всегда пробуется первой; если она совпадает с моделью из цепочки, дубль
удаляется и порядок цепочки сохраняется. Чтобы изменить список запасных —
отредактируйте `FALLBACK_MODELS`.

Если выбран провайдер **OpenAI**, используется отдельная цепочка `OPENAI_FALLBACK_MODELS`
(`gpt-4o-mini → gpt-4o`) — обе модели мультимодальные, поэтому один список
работает и для текста, и для vision (сканы, фото, PDF без текстового слоя).

## Структура

| Файл | Назначение |
|------|-----------|
| `manifest.json` | Manifest V3, host-permissions, регистрация скриптов. |
| `background.js` | Service worker: весь пайплайн и сетевые запросы (Notion, OpenRouter, КГД). |
| `offscreen.html` + `offscreen.js` | Скрытый документ расширения для извлечения текста PDF через PDF.js в MV3. |
| `content.js` + `styles.css` | Плавающая кнопка и тост прогресса на странице Notion. |
| `popup.html` + `popup.js` | Форма настроек (хранится в `chrome.storage.local`). |
| `lib/pdf.min.mjs`, `lib/pdf.worker.min.mjs` | `pdfjs-dist` (legacy build), забандлен локально. |
| `icons/` | Иконки расширения. |

## Обновление pdf.js

```
npm install pdfjs-dist@<версия>
cp node_modules/pdfjs-dist/legacy/build/pdf.min.mjs lib/
cp node_modules/pdfjs-dist/legacy/build/pdf.worker.min.mjs lib/
```

Версия зафиксирована в `package.json` (текущая — `pdfjs-dist@4.7.76`).
